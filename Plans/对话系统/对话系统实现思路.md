# 对话系统实现思路

## 1. 目标与特点

本项目的对话系统采用“CSV 数据驱动 + 运行时状态机 + UI 订阅显示”的实现方式。  
与常见对话系统相比，本系统的核心差异在于：**引入了应激度对选项的影响**。  
具体表现为：

1. 对话选项在显示前，需要先读取当前应激度。
2. 不同应激度下，部分选项会出现、隐藏或禁用。
3. 玩家选择某个选项后，会反过来影响应激度。
4. UI 只负责显示，不直接修改核心状态。

整体链路参考当前流程图：

`CSV导入 -> 解析CSV -> DialogueGraphData -> DialogueRunner -> DialogueView`

其中：

- `DialogueGraphData` 是运行时使用的对话数据图。
- `DialogueRunner` 是游戏内对话推进与分支决策的核心。
- `DialogueView` 是界面显示层，负责姓名、立绘、文本、按钮等 UI。


## 2. 总体架构

建议将系统拆成以下几个模块：

### 2.1 DialogueCsvImporter

负责读取 `DialogueNodes.csv` 和 `DialogueChoices.csv`，并转换为运行时数据结构。

职责：

- 读取两张 CSV 表。
- 解析节点与选项字段。
- 将节点与选项组装成可运行的数据图。
- 做基础校验，例如：
  - `NodeId` 是否唯一。
  - `ChoiceId` 是否唯一。
  - `NextId` 是否存在对应节点。
  - `Choice` 所属的 `NodeId` 是否有效。

输出：

- `DialogueGraphData`


### 2.2 DialogueGraphData

作为对话系统的运行时数据容器，负责保存整套对话图。

建议包含：

- 节点字典：`NodeId -> DialogueNodeData`
- 选项映射：`NodeId -> List<DialogueChoiceData>`

其中：

- `DialogueNodeData` 保存说话人、立绘、文本、默认 `NextId`
- `DialogueChoiceData` 保存选项文本、跳转目标、应激变化、阈值范围

这样运行时可根据当前节点快速拿到：

- 当前要显示的对话内容
- 当前节点对应的所有候选选项


### 2.3 DialogueRunner

这是整个系统的核心，负责推进对话、生成选项、处理玩家选择，以及与应激度系统交互。

职责：

1. 启动对话  
   根据传入的起始 `NodeId`，加载首个节点。

2. 播放当前节点  
   把当前节点数据发送给 UI，包括：
   - 说话人姓名
   - 立绘
   - 对话文本

3. 等待文本完成  
   文本使用打字机效果显示。  
   当文本播完后，进入以下两种情况之一：
   - 若当前节点没有选项：显示“下一句”按钮
   - 若当前节点有选项：先过滤选项，再显示选项按钮

4. 过滤选项  
   在显示选项前读取当前应激度，并根据 `ThresholdLow` / `ThresholdHigh` 判断该选项是否可见或可交互。

5. 处理选项点击  
   玩家点击选项后：
   - 调用应激度系统接口修改应激度
   - 获取该选项的 `NextId`
   - 跳转到下一个节点继续对话

6. 处理无选项跳转  
   若当前节点无选项，则点击“下一句”按钮后跳到节点的 `NextId`

7. 对话结束  
   当节点没有有效 `NextId`，并且也没有选项时，对话结束。


### 2.4 MentalStatsManager

根据你们现有规则，应激度必须集中管理，不能由 UI 或其他模块直接写值。

在对话系统里，它主要承担两件事：

1. 提供当前应激度给 `DialogueRunner` 做选项过滤。
2. 在玩家做出选择后，通过公开接口修改应激度，并触发状态变化广播事件。

推荐交互方式：

- `DialogueRunner` 只读取状态，或调用类似 `ModifyStress(int value)` 的公开接口。
- `MentalStatsManager` 在数值变化后统一广播事件，例如 `OnStatsChanged`。

这样可以保证：

- 单一数据源明确
- UI 不反向改核心状态
- 后续特效变化或其他系统也能复用同一套状态广播


### 2.5 DialogueView

`DialogueView` 是纯 UI 层，只订阅 `DialogueRunner` 提供的数据与状态，不负责业务判断。

UI 至少包含以下元素：

1. 说话人立绘
2. 说话人姓名
3. 对话框
4. 跳转到下一句话的按钮
5. 选项按钮列表

可拆分为几个子组件：

- `PortraitPresenter`：显示立绘
- `NamePresenter`：显示姓名
- `DialogueTextPresenter`：显示文本
- `NextButtonPresenter`：显示/隐藏“下一句”按钮
- `ChoiceListPresenter`：生成和回收选项按钮

这样便于后期替换 UI 风格，而不影响核心逻辑。


## 3. 数据设计

当前使用两张表：

### 3.1 `DialogueNodes.csv`

节点表描述一条对话内容本身。

当前字段：

- `NodeId`
- `SpeakerName`
- `PortraitKey`
- `Text`
- `NextId`

含义：

- 一个 `NodeId` 代表一条实际要显示的对白或旁白
- 如果该节点没有选项，就通过 `NextId` 继续推进


### 3.2 `DialogueChoices.csv`

选项表描述一个节点下有哪些玩家选择。

当前字段：

- `ChoiceId`
- `ChoiceOrder`
- `NodeId`
- `OptionText`
- `NextId`
- `StressModifier`
- `ThresholdLow`
- `ThresholdHigh`

含义：

- `NodeId` 用于把选项挂到某个节点下
- `OptionText` 是显示给玩家看的文字
- `NextId` 是该选项选中后的跳转目标
- `StressModifier` 是选中该选项后对应激度的变化量
- `ThresholdLow / ThresholdHigh` 用于判断该选项在当前应激度下是否出现


## 4. 运行流程

建议的对话运行流程如下：

### 4.1 进入对话

1. 外部系统触发一次对话开始，例如交互、剧情事件或场景触发器。
2. `DialogueRunner.StartDialogue(startNodeId)` 被调用。
3. `DialogueRunner` 从 `DialogueGraphData` 中读取当前节点数据。


### 4.2 显示当前节点

1. `DialogueRunner` 将当前节点数据发给 `DialogueView`
2. `DialogueView` 更新：
   - 立绘
   - 姓名
   - 文本内容
3. 文本开始执行打字机效果


### 4.3 文本播放结束后的分支

文本播放完成后分两种情况：

#### 情况 A：当前节点没有选项

1. 显示“下一句”按钮
2. 玩家点击按钮
3. `DialogueRunner` 读取当前节点 `NextId`
4. 跳转到下一个节点

#### 情况 B：当前节点存在选项

1. `DialogueRunner` 先读取当前应激度
2. 遍历该节点下的所有选项
3. 根据阈值决定：
   - 显示
   - 隐藏
   - 或禁用
4. `DialogueView` 生成可见选项按钮


### 4.4 玩家选择选项

1. 玩家点击某个选项按钮
2. `DialogueRunner` 获取该选项数据
3. 调用 `MentalStatsManager.ModifyStress(StressModifier)`
4. 应激度系统更新应激度
5. 状态变化事件对外广播
6. `DialogueRunner` 根据该选项的 `NextId` 跳转下一节点
7. 继续执行下一轮显示流程


### 4.5 对话结束

当满足以下任一条件时，对话结束：

1. 当前节点没有 `NextId`
2. 当前节点没有选项，且文本结束后不再跳转
3. 外部系统主动中断对话

结束时应：

- 关闭对话 UI
- 清理当前节点状态
- 清理选项按钮


## 5. 应激度机制与普通对话系统的差异

普通对话系统通常只负责：

- 显示文本
- 播放头像/名字
- 处理分支跳转

而本项目的对话系统额外承担了“应激度反馈”的玩法功能。

### 5.1 选项受应激度影响

当前应激度会影响玩家“能看到什么选项”。

例如：

- 低应激状态下，可以出现更理性、更冷静的选项
- 高应激状态下，冷静选项可能被隐藏，只保留冲动或异常的选项

这意味着：

- 对话系统不只是表现层
- 它实际上已经成为应激度玩法的一部分


### 5.2 选择会反向影响应激度

玩家不是只在“选剧情分支”，而是在“选心理倾向”。

例如：

- 选择平静、回避、自我安抚类选项时，应激度可能下降
- 选择偏执、惊慌、失控类选项时，应激度可能上升

这使得对话形成了一个闭环：

`当前应激度 -> 影响可选内容 -> 玩家选择 -> 修改应激度 -> 继续影响后续选项`

这是本项目与常规 AVG 对话系统最关键的区别。


## 6. UI 实现建议

由于当前只打算使用一种对话框样式和一套固定音效策略，因此可以把 UI 做成一个固定面板 Prefab。

建议结构：

- `DialoguePanel`
  - `PortraitImage`
  - `SpeakerNameText`
  - `DialogueText`
  - `NextButton`
  - `ChoicesRoot`

交互建议：

1. 文本播放中  
   - “下一句”按钮可用于跳过打字机，直接显示全文

2. 文本播放完成且无选项  
   - “下一句”按钮用于推进到下一节点

3. 文本播放完成且有选项  
   - 隐藏“下一句”按钮
   - 显示选项列表

4. 切换节点时  
   - 清空上一个节点遗留的选项按钮
   - 更新立绘与文本


## 7. 推荐的最小实现顺序

为了先做出可运行版本，建议按以下顺序实现：

### 阶段 1：跑通最小链路

- 完成 `DialogueNodes.csv` / `DialogueChoices.csv` 的读取
- 完成 `DialogueGraphData`
- 完成 `DialogueRunner` 的基本跳转
- 完成基础 `DialogueView`
- 能显示一段文字，并在点击后跳到下一句


### 阶段 2：加入选项

- 支持一个节点对应多个选项
- 点击选项后跳转到不同节点
- 支持选项排序显示


### 阶段 3：接入应激度

- `DialogueRunner` 接入 `MentalStatsManager`
- 根据阈值过滤选项
- 选中选项后修改应激度


### 阶段 4：完善表现

- 打字机效果
- 固定音效，包括打字机效果中字弹出音效，选项点击音效
- 选项禁用/隐藏样式区分


## 8. 总结

本系统不适合使用传统“纯展示型”对话实现，而应采用“数据驱动 + 状态驱动”的设计。  
CSV 负责定义叙事节点与选项，`DialogueRunner` 负责推进与决策，`MentalStatsManager` 负责应激度计算与管理，`DialogueView` 负责界面显示。  
其中最关键的设计点是：**应激度参与选项生成，玩家选择又反过来影响应激度**。  
只要这条链路保持清晰，后续无论增加历史记录、跳过、自动播放、更多 UI 皮肤，还是扩展到剧情事件联动，都可以在现有结构上继续迭代。
