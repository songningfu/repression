对话系统 CSV 字段说明（两张表：节点表 + 选项表）
==========================================

约定
----
1. `DialogueNodes.csv`：描述“叙事节点（一条要显示的对话/旁白）”以及“无选项时的下一跳”。
2. `DialogueChoices.csv`：描述“某个节点下有哪些选项、选中后跳到哪里、以及应激度如何变化/如何参与过滤”。
3. 运行时规则建议：
   - 若某 `NodeId` 在选项表中存在选项，则该节点进入“等待选择”流程；此时 `DialogueNodes.csv` 的 `NextId` 可以忽略。
   - 若某 `NodeId` 没有选项，则直接使用 `DialogueNodes.csv` 的 `NextId` 作为下一节点。


一、节点表：`DialogueNodes.csv`
-----------------------------

1) `NodeId`
- 含义：节点的唯一标识符（主键）。
- 用途：用于让 `NextId` / `NextIdOnChoice` 指向该节点；也用于把本节点与其选项关联（`DialogueChoices.csv.NodeId`）。
- 规则：在整套 CSV 中应当唯一。

2) `SpeakerName`
- 含义：对话框里显示的说话人名字（也可以是“说话人 ID”，由你们自行决定 UI 如何映射）。
- 用途：UI 在 `OnLineStart` 时把该字段显示到姓名区域。

3) `PortraitKey`
- 含义：立绘/头像资源的“键”（字符串）。
- 用途：UI 根据该键从你们的资源表/字典里找到对应 Sprite/图标并显示。

4) `Text`
- 含义：该节点要显示的正文内容。
- 用途：跑字机（打字机）把这段文本逐步显示出来。
- 备注：若你们文本支持变量替换，本字段就是替换后的源文本（Runner 或文本适配层负责替换）。

5) `NextId`
- 含义：当该节点“没有选项”时，玩家确认继续后要跳到的下一节点 ID。
- 用途：Runner 结束当前节点后推进到 `NodeId = NextId`。
- 规则：当存在选项时，建议 Runner 进入选项流程，`NextId` 可忽略。


二、选项表：`DialogueChoices.csv`
--------------------------------

1) `ChoiceId`
- 含义：选项的唯一标识符（主键）。
- 用途：运行时如果你们要用“选择 ID”做回调/日志/定位，也会用到它；也可用于客户端（UI）向 Runner 回传。

2) `ChoiceOrder`
- 含义：选项显示顺序（从小到大）。
- 用途：UI 生成按钮/列表时按照该字段排序。

3) `NodeId`
- 含义：该选项所属的节点 ID（外键）。
- 用途：把选项绑定到 `DialogueNodes.csv.NodeId`，形成“节点 -> 选项列表”。

4) `OptionText`
- 含义：按钮上显示的选项文本。
- 用途：UI 渲染用。

5) `NextId`
- 含义：玩家选中该选项后要跳转到的下一节点 ID。
- 用途：Runner 在选中后推进到 `NodeId = NextId`。

6) `StressModifier`
- 含义：玩家选中该选项后，对“应激度”的变化量（加减值或档位，取决于你们 MentalStatsManager 的实现）。
- 用途：Runner 在选中选项后调用应激系统公开接口更新应激度，然后触发状态广播。
- 示例语义（建议）：  
  - `+12` 表示选中后更紧张（应激度增加 12）  
  - `-10` 表示选中后更冷静（应激度减少 10）
- 重要：应激度的更新必须走 `MentalStatsManager` 的明确接口，不要在 UI 直接改核心数值。

7) `ThresholdLow`
- 含义：应激度过滤区间的下界。
- 用途：用于决定该选项在“当前应激度”条件下是否可用/可见。

8) `ThresholdHigh`
- 含义：应激度过滤区间的上界。
- 用途：用于决定该选项在“当前应激度”条件下是否可用/可见。

9) 区间语义（必须在实现里定死）
- 建议默认语义（与你们示例 CSV 的用法一致）：当 `CurrentStress` 落在 `[ThresholdLow, ThresholdHigh]`（是否包含端点可在实现里统一）时，该选项“可用/可见”；否则“隐藏或禁用”。
- 如果你们 A2 的目标需要“隐藏冷静选项”而不是“放行区间”，只要在 Runner 里把判断逻辑翻转即可：  
  - 例如：当落在冷静阈值区间时隐藏该选项，其他区间显示它。


补充说明：为何没有 `DialogBoxType/Style` 与 `SfxKey`
----------------------------------------
你之前说“对话框样式和音效只使用一种”，因此示例里没有把 `DialogBoxType/Style` 和 `SfxKey` 放入 CSV。
建议做法是把它们配置到：
1) 对话 UI 的固定 Prefab/Inspector 配置，或
2) Runner 的一个全局配置（比如 `DialogueUiConfig` ScriptableObject）
这样 CSV 的数据只关心“叙事与分支”，UI 层负责渲染与声音策略。
