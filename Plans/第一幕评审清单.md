## 二、系统能力缺口（剩余内容卡在这些地方）

> 这是评审的核心：剩余 6 个场景不是"多写点 CSV"就能完成，它们依赖以下尚未具备的系统能力。

### 阻塞型缺口（不解决就做不了对应场景）

| # | 缺口 | 被哪些场景需要 | 现状 | 影响 |
|---|---|---|---|---|
| G1 | **剧情标志位 / Flag 系统** | 场景八 | 无 | 对话 CSV 当前只支持"按应激度阈值过滤选项"，不支持"序幕是否提过糖糕""是否已获得线索"这类条件分支/一次性事件 |
| G2 | **线索系统 / 线索板** | 场景八、十 | 无 | 剧本要求获得线索碎片①②并记录到线索板；目前无数据结构与 UI |
| G3 | **治疗训练小游戏（自由绘画/描红轨迹跟随）** | 场景八 | 无 | 需画笔轨迹检测、完成度判定(>80%)、暖色铅笔选择影响后续暗示 |
| G4 | **噩梦/闪现演出系统** | 场景六、十 | 无 | 需按序播放"画面闪现+浮现文字+音效"的过场序列，非对话框能表达 |
| G5 | **序幕(Prologue)内容** | 场景八引用 | 未进游戏 | 糖糕/吴良/陆云初印象等均在序幕建立；序幕本身还没做 |

## 三、与已完成内容无关、但第一幕可玩必须补的工程项

- **场景拼装**：`Reality_Room` / `Reality_Street` 尚未用第一幕分层美术(室内房间/街道)搭建。
- **场景内对话挂接**：各交互物体(冰箱/书桌/床头柜/手机/镜子/便利店老板/床)需挂 `DialogueTrigger + DialogueFInteractController` 并绑定 StartNodeId；`DialogueRunner + DialoguePanel` 需放入场景（Editor 手动绑定，项目约定）。
- **流程闭环**：主菜单、序幕过场、存档、场景流转(房间→街道→医院→咨询室)均缺。

## 四、建议的决策点

1. **优先级**：是先"把前 4 个场景做成真正可玩的垂直切片"（拼场景+挂对话+联调），还是先"继续铺对话内容"（场景五/七等不依赖新系统的部分）？
   - 倾向：先做**可玩垂直切片**，因为它能验证对话/应激/灰度系统在真实关卡里是否成立，价值高于继续堆文本。
2. **系统扩展排期**：G1(Flag) + G2(线索) 是咨询室与后续幕次的公共底座，建议优先于"咨询室内容"开发。
3. **演出与小游戏**：G3(绘画小游戏) + G4(闪现演出)工作量大，建议单独立项评估，不与对话内容混做。
4. **序幕**：场景八强依赖序幕，建议把序幕(已有 docx)纳入与咨询室同一批次。
